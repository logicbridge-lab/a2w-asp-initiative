# A2W/ASP Research Report: Agent-to-Web Standard and Agentic Site Profiles

## Abstract

This report introduces the concept of an Agent-to-Web (A2W) standard and its corresponding site-level implementation, the Agentic Site Profile (ASP). As autonomous agents increasingly interact with websites on behalf of humans, the gap between human-optimized web interfaces and machine-usable site descriptions grows more costly. We propose that a lightweight, domain-published, machine-readable profile can dramatically improve the reliability, safety, efficiency, and auditability of agent-web interactions without requiring changes to the human-facing web. This report frames the problem, sketches the standard, defines an initial schema, and outlines a research and bootstrap program.

## Problem Statement

The web was designed for human readers using graphical browsers. HTML semantics, visual layout, navigation structure, and interactive elements are all optimized for people. Autonomous agents that need to use websites as tools or data sources must reverse-engineer this human interface through DOM parsing, visual analysis, and brittle heuristics.

This creates several categories of failure. Agents misinterpret page structure, click the wrong elements, or fail to find the right action path. There is no standard way for a site to declare what it supports, what it prohibits, and how to interact with it correctly. The result is fragile integrations, high engineering cost per site, and governance blind spots for both site operators and agent users.

## The A2W Standard

A2W (Agent-to-Web) is a proposed open standard for structured interaction between autonomous agents and websites. It defines how an agent discovers a site's machine-facing description, how that description is represented, and how it informs safe and efficient agent behavior. A2W does not replace the human web. It adds a machine-native contract beside it, analogous to how robots.txt provides simple policy signals but far richer in structure and capability.

## The ASP Schema

The Agentic Site Profile (ASP) is the site-level document that implements A2W. A domain owner publishes an ASP as a machine-readable manifest declaring identity, capabilities, policies, and interaction patterns for autonomous agents. A minimal ASP contains the following fields.

domain identifies the site the profile applies to. owner declares who maintains the profile and how to contact them. version tracks the profile's own revision to support evolution without breaking existing consumers. scope defines the subset of the site covered by the profile, which may be the entire domain or a specific subdirectory or service.

resources list the major machine-usable surfaces of the site, each with a path, a content type, and a description of what the resource provides. These are analogous to API endpoints but may also describe pages and data feeds.

actions enumerate the operations an agent can perform on the site, such as search, book, submit, purchase, or query. Each action includes parameters, expected input structures, output formats, and preconditions. This is the core of the profile from an agent's perspective.

policies declare constraints on agent behavior at a granularity finer than robots.txt. They cover rate limits, authentication requirements, data usage restrictions, and prohibited actions.

workflows describe multi-step procedures that combine several actions into a coherent task, such as scheduling a consultation or filing a claim. Each workflow links to the relevant actions and specifies the expected sequence.

auth describes authentication requirements and mechanisms. This may be none for public sites, API key for registered services, or OAuth flows for user-specific operations.

evidence links to the evidence used to generate the profile, if the profile was inferred rather than authored by the domain owner. This field is critical for the bootstrap phase when most profiles will be draft ASPs generated by automated analysis.

observability specifies what telemetry the site exposes about agent interactions, such as request logs, rate limit headers, or status endpoints.

## Bootstrapping the Open Corpus

The central challenge of A2W/ASP is adoption. A standard with no implementations is not useful. An implementation with no sites to connect to is not valuable. We break this chicken-and-egg problem by running a bootstrap program that generates inferred ASP Drafts for publicly accessible sites and publishes them as an open corpus.

The bootstrap pipeline has four stages. First, a polite, robots-aware crawler collects HTML, metadata, and optional screenshots from target domains. Second, a structural extraction stage uses heuristics and model-assisted classification to infer page purpose, navigation structure, form semantics, and candidate actions. Third, an ASP generation stage compiles the evidence into a structured draft profile with confidence scores per field. Fourth, a monthly release packages the crawl artifacts, ASP Drafts, and benchmark results for public distribution.

The resulting corpus serves three purposes. It demonstrates the feasibility of the approach. It provides raw material for academic research. And it creates immediate practical value for agent developers who can use the draft profiles to improve their systems.

## Benchmarking

To validate the hypothesis that ASP-guided interaction outperforms raw web inference, we design a benchmark suite covering common agent tasks across multiple site categories. Each task is attempted under two conditions: raw web access with no profile, and ASP-guided access using the inferred draft profile.

Metrics include task success rate, number of steps to completion, total latency, ambiguity events where the agent must choose between multiple plausible actions, and policy violations where the agent attempts a prohibited action.

The benchmark is designed to be reproducible and extensible. Other researchers can add tasks, site categories, or agent implementations and compare results against the published baseline.

## Organizational Context

LogicBridge is a Toronto-based AI lab building small, quantized, domain-specific models and trusted workflow tools for Canadian SMEs. A2W/ASP aligns directly with the company's focus on governance-aware systems, domain-controlled infrastructure, and practical model deployment. It complements the Myra product line by enabling agents to navigate the web more reliably. It leverages existing MCP server expertise from Sentinel, Loom, and Prism. And it establishes LogicBridge as a standards-setting player in the growing agent ecosystem.

## Next Steps

The immediate next steps are to finalize the ASP schema, build the initial crawler and extraction pipeline, generate a pilot corpus of 100-500 sites, publish the research paper of intent, and open the public repository for community contributions. The goal is to have a first monthly release within 90 days of project initiation.

## Conclusion

The gap between human-optimized websites and machine-needs is real, growing, and costly. A2W/ASP offers a lightweight, domain-controlled solution that can be bootstrapped through an open corpus of inferred profiles and validated through rigorous benchmarking. The standard is simple enough to adopt, the corpus is valuable enough to use, and the research program is structured enough to produce credible results. This initiative has the potential to become a foundational layer of the agent internet.
